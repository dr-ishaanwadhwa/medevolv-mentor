01What it is and where it stands

MedEvolv Mentor is a retrieval-augmented chatbot (RAG). It never answers from the language model's memory. It first finds evidence in the textbooks, and for clinical cases also in a medical knowledge graph, then asks the model to write an answer using only that evidence, citing each claim. When the evidence isn't there it says so.

Build steps

  1. 1Check each PDF (ingest/check_books.py): ToC depth, text per page and a verdict, one of OK, NO_TOC, SCANNED or SHALLOW_TOC.
  2. 2Cut sections at bookmark positions (ingest/pdf_to_okf.py): text is sliced at the bookmark's exact spot on the page, so nothing is duplicated or split mid-heading. Running headers and margin tabs are stripped. Chapter intros become "Overview" sections. Measured coverage is 99–101% of each book's text.
  3. 3Write an OKF bundle: one markdown file per section with YAML metadata (book, chapter, section path, pages), plus toc.json and index.md per book under data/okf/.
  4. 4Chunk (rag/chunk.py): heading-aware passages of up to ~300 words. Tiny fragments are merged, and every passage carries its book, chapter, section path and pages.
  5. 5Embed and index (rag/index.py): bge-small vectors in Chroma under data/chroma/. This takes about 6 minutes on a Mac.

04What happens to a question

  1. 1Safety check (rag/answer.py: _guard): a regex catches requests about a real person, such as "my mother…", "should I take…" or "how much should I give…". These are declined before any search.
  2. 2Symptom linking (rag/graph.py: link_entities): exact names, lay terms with generic prefixes, and a semantic fallback (similarity ≥ 0.86) map phrases to BODHI symptom nodes.
  3. 3Routing (rag/hops.py: plan):
    • Clinical case: 2 or more symptoms, or 1 symptom plus a case cue ("patient", "year old", "presents", "diagnosis") → graph route.
    • Compound: "compare", "difference", "vs", several "?", or "and why/how" → split into up to 3 sub-questions by the LLM.
    • Otherwise: one direct search.
  4. 4Graph hops (clinical case only): conditions are ranked by matched symptoms, weighted by BODHI's likelihood labels (top 3). Then specialists and drugs come from the graph, with drugs found via CHILD_OF ancestors. For the top 2 conditions, the textbooks are searched for "treatment and drug of choice for X".
  5. 5Search (rag/retrieve.py): cosine similarity over all 33,830 passages, returning the top 6, or 3 per sub-question.
  6. 6Relevance filters:
    • The best passage must score ≥ 0.60, or the bot declines without calling the model.
    • On the graph route, a passage counts as being about a condition only if it actually names it.
    • At most 9 passages go to the model.
  7. 7Grounded answer: DeepSeek gets numbered passages [1]…, graph facts [G1]…, and rules: answer only from the evidence, cite every claim, say which parts aren't covered, and reply INSUFFICIENT_CONTEXT if nothing answers it. That reply makes the bot decline.
  8. 8Checks: every [n] is validated against the evidence list. Drugs named in the answer are cross-checked against the graph's drug links. Echoed headers are stripped from the answer.
Three ways it says no: personal advice (before search), weak retrieval (best match below 0.60, model never called), and the model's own check (INSUFFICIENT_CONTEXT).

05The answer trace and the UI

rag/trace.py records each step of a question: stage, title, plain-language detail, status (ok, warn or stop) and duration. Every vector search and every LLM call is captured automatically at retrieve.search and backends.chat. Routing, graph, filter and citation decisions record themselves where they happen. Outside the app nothing is recorded, so the CLI and the evaluation harness are unaffected.

Ask tab

  • Six demo questions, labelled by type
  • A live status box that ticks off steps as they run
  • Under each answer: How this answer was made (timeline with timings, search results with score bars, model and token counts) and Sources (cited or retrieved, book, match score, path, pages, 300-character excerpt)
  • Sidebar: multi-hop on/off for a before-and-after comparison

  • Two flow diagrams: question time and the offline build

07Run it on your machine

The repo has no books or index (see section 14). To run it fully you need the PDFs in data/books/, named by ISBN. Ask Ishaan for access.

git clone https://github.com/dr-ishaanwadhwa/medevolv-mentor && cd medevolv-mentor
python3.13 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python -m ingest.fetch_bodhi             # graph data -> data/bodhi/
# put PDFs in data/books/, then run the per-book ingest commands in README.md
.venv/bin/python -m rag.index                      # ~6 min: embed 33,830 passages
echo "DEEPSEEK_API_KEY=...your key..." >> .env    # never commit .env
echo "LLM_BACKEND=deepseek" >> .env
.venv/bin/streamlit run app.py                     # http://localhost:8501
.venv/bin/python -m pytest -q                      # 23 tests
.venv/bin/python -m eval.product_eval              # 36-question evaluation

Offline fallback: LLM_BACKEND=ollama with OLLAMA_MODEL=qwen2.5:7b, which is better than the default 3B model. Run ollama pull qwen2.5:7b first.

Redeploy after a change

DOMAIN=mentor.medevolv.in deploy/oci/push.sh 130.210.60.153

This builds the bundle (code, theme, graph data and a compacted index, with no books), uploads it, copies only the DeepSeek key (and the password, if set) to the server, rebuilds the image and recreates Caddy. It takes 1–3 minutes when cached.

Gotchas we hit:
  • Never run two push.sh at once: each builds a fresh index folder, and rsync --delete makes the runs delete each other's files.
  • Always pass DOMAIN, or Caddy stops serving the domain's certificate.
  • Oracle's Ubuntu image blocks ports 80/443 in iptables even when the security list allows them; setup.sh opens them.
  • The new-VCN wizard doesn't attach a public IP. Add an ephemeral one under VNIC → IP administration (the ⋯ menu opens with Enter).
  • The first question after a deploy takes about 12 s while the embedding model loads. Warm it up before a demo.

Logs: ssh … 'cd eka && sudo docker compose logs -f app'. Full notes in docs/deploy_oci.md.

13Demo script (about 5 minutes)

  1. 0Before the professor arrives: open the site and ask any question once, to warm up the model.
  2. 1How it works tab (1 min): the question-time diagram and the three refusal rules.
  3. 2Mosquito case (1.5 min): open "How this answer was made". Show the symptoms linked, the graph's conditions, the textbook search, the relevance filter and the cited answer.
  4. 3Penicillins vs aminoglycosides (45 s): the question splits into two searches, so both drug classes get evidence.
  5. 4Cricket question, then "My mother has TB…" (45 s): one is declined below the 0.60 threshold without calling the model, the other before any search.
  6. 5Multi-hop off (30 s, optional): the same question as plain RAG, for contrast.
  7. 6Close (1 min): the evaluation table, the honest limits (TB vignette) and next steps.

Backup: if the network fails, run the app on a laptop with LLM_BACKEND=ollama, OLLAMA_MODEL=qwen2.5:7b.

14Rules: copyright and secrets

The textbook PDFs are unlicensed copies. They, and everything derived from them (OKF bundle, Chroma index, STAIR pairs and adapters, evaluation outputs), stay out of git. They're all git-ignored and never were committed. Never upload them to a public place, a public Kaggle dataset or a public Space. Move to institutional access before any real release.
  • Live site: it's public and shows up to 9 excerpts of 300 characters per answer. This was a deliberate team decision for the demo, with noindex to stay out of search results. To re-gate it, uncomment APP_PASSWORD in .env and redeploy.
  • Secrets live only in .env (git-ignored) and in the server's ~/eka/.env (mode 600). Never paste keys into chat, issues or docs.
  • Data flow: every answer sends up to 9 passages and the question to DeepSeek's API.
  • Attribution: credit Eka Care for BODHI wherever the graph is shown (CC BY-NC 4.0: credit, non-commercial).

15Adding a book

Adding a book takes no code changes to the pipeline. Each book is one ingest command with its own section levels. Capacity isn't a concern: the VM has 12 GB RAM and 42 GB free disk, and Chroma searches 50k+ passages in milliseconds.

Added book: Harrison's Principles of Internal Medicine (22nd ed.), from the team's own list.
  • It fixes gaps we've already seen. In the mosquito demo the answer had to say the indexed books don't cover acute dengue management. TB and measles are the weak vignettes too. Harrison's covers all of these in depth.
  • It strengthens the clinical-case route, the most impressive part of the demo, where the textbook confirms what the graph proposes.
  • Cost: it's about 4,000 pages, so expect the index to roughly double or triple (about 15–20 minutes to rebuild, and a bigger deploy bundle).
Cheaper alternative: Harper's Illustrated Biochemistry (32nd ed.). It adds a sixth core subject the app can't answer at all today, and it's a small book.
Not before the 17 Nov demo. Neither PDF is on disk yet, and a re-index plus redeploy is avoidable risk on demo day. Add it the week after, and check the PDF first with check_books (step 1).
  1. 1Put the PDF in data/books/, named by ISBN, and run python -m ingest.check_books data/books. You need verdict OK. NO_TOC means rebuilding headings from fonts (ingest.font_toc, like Tripathi). SCANNED means the PDF has no text layer and needs OCR first.
  2. 2Run ingest.pdf_to_okf with the right --level and --chapter-level, and --also-skip for front matter. Copy the pattern from README.md.
  3. 3Open data/okf/<book>/index.md and check the sections and coverage. A domain expert skim takes 10 minutes.
  4. 4Re-index with python -m rag.index, which rebuilds the whole index (about 6+ minutes).
  5. 5Add the book to BOOKS in app.py, the subject list in rag/answer.py: SYSTEM, and the counts on the How it works tab and in this handbook.
  6. 6Add 3–5 questions to eval/product_questions.jsonl, run the tests and the product evaluation, then redeploy.
